# Contributing to CyberLabKit

Thank you for helping make cybersecurity education more practical and accessible.

## Before contributing

- Keep examples inside authorized, isolated labs.
- Never include credentials, tokens, personal data, or private logs.
- Do not add automation designed to attack third-party systems.
- Prefer reproducible examples with clear prerequisites.
- Explain the educational goal of each lab.

## Suggested contributions

- New beginner-friendly labs
- Defensive exercises
- Log-analysis datasets created for education
- Documentation improvements
- Tests
- Translations between Spanish and English
- Accessibility improvements

## Pull requests

1. Open an issue describing the proposed change when practical.
2. Keep each pull request focused.
3. Include tests for code changes.
4. Document safety assumptions.
5. Explain how another learner can reproduce the result.
